# 从位图曲线图里读出数值（无 OCR / 无原始数据）

**何时用**：论文（或审稿意见）只给出曲线图，而你需要引用/核对具体数值。
例：审稿意见说 "at 60% load it seems to be much more than 5.8% worse" —— 你要把图上 60% 处的实际差距读出来。

现成脚本：`scripts/extract_figure_curves.py`（纯 PIL，须用 `terminal` 跑；execute_code 沙箱无 PIL）。
下面是手工推演一遍的步骤，脚本失败时按此回退。

## 步骤

1. **先做颜色直方图**，找出各序列的配色（排除白/灰/黑）：
   ```python
   from PIL import Image; import collections
   im = Image.open(p).convert('RGB'); W,H = im.size; px = im.load()
   cnt = collections.Counter()
   for y in range(0,H):
       for x in range(0,W):
           r,g,b = px[x,y]
           if max(r,g,b)-min(r,g,b) < 50 or max(r,g,b) < 60: continue
           cnt[(r//20*20,g//20*20,b//20*20)] += 1
   print(cnt.most_common(15))
   ```
   得到如 red(240,0,0)=EDFLet、blue(60,120,180)=CONGA、yellow/amber=Clove、green=LetFlow、orange=DRILL。
   配色→方案的映射**必须从图例确认**（裁剪图例区域单独看图，别猜）。

2. **标定 y 轴**：找水平网格线——整行里大量「低饱和、中亮度」（灰）像素的行。
   ```python
   for y in range(H):
       grey = sum(1 for x in range(0,W,3)
                  if (lambda c: max(c)-min(c) < 18 and 150 < sum(c)/3 < 242)(px[x,y]))
       if grey > (W//3)*0.45: print('gridline row', y)
   ```
   相邻网格线像素间距应恒定（如 220.5px / 200 单位）。配上 y 轴刻度文字即得 `row:value`。
   底部坐标轴（粗黑线，`r,g,b<120` 占比高）通常就是最低那条刻度。

3. **标定 x 轴**：数据点分布成列的峰值即 x 刻度像素列，间距应等距。
   对每个序列输出「每 40px 一格的像素密度直方图」，峰值列即标记列。

4. **读标记值**：在每个 x 刻度像素列 ±20px 的竖条里，收集该配色像素，取「最密的 17px 带」的中心行
   （标记是实心块，比连线密），换算成数值。

5. **反校验（关键）**：拿一个**已知**数值点验证标定。例：80% 负载处读出的差距 6.0% ≈ 论文写的 5.8%
   → 标定可信；否则重做第 2 步。没有已知点就无法保证 ±1% 精度，务必把结论标为近似值。

## 坑

- **图例遮挡**：图例常压在数据上方，且与高负载数据点同 y 区间。用 `--exclude-rows` 屏蔽图例行带；
  但注意别把落在该带内的真实数据点也屏蔽掉（例：60% 处 DRILL 的点恰在图例带里 → 该点读数不可信，弃用）。
- **标记 vs 连线**：同一颜色既有细连线又有实心标记；「最密带」取标记，「颜色 y 跨度」会被连线拉长，别当成误差棒。
- **PDF 图**：脚本只吃位图。PDF 先转：`pdftoppm -r 300 in.pdf out` 或 pymupdf `page.get_pixmap()`。
- **等距假设**：x 刻度等距（20/40/60/80）才可用「峰值列」当刻度；若不等距，需读轴标签文字位置定标。
- 结果一律标注为「按图读出的近似值，请用原始仿真数据核对」——不要把它当权威数字写进论文。
