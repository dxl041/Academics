# 论文+配套白皮书联合分析模式

当一篇论文有配套的技术规范/白皮书/技术报告时，两篇文档互补性强，联合分析能获得更完整的技术理解。

## 适用场景

- 工业论文 + 协议规范（如 MRC 论文 + MRC Specification 白皮书）
- 系统论文 + 延伸技术报告
- 会议论文 + arXiv 长版本

## 文档关系判断

论文通常回答"做了什么+为什么+效果如何"，白皮书/规范回答"协议具体长什么样"。两者互补：
- 论文说"禁用了 PFC" → 白皮书解释如何做到（DSCP 分类 + trim + NSCC）
- 论文说"EV 自动绕过故障" → 白皮书定义 EV 四状态机 + 转换条件
- 论文说"快速选择性重传" → 白皮书定义 SACK bitmap、触发器、NACK 类型

## 分析流程

### 1. 并行提取（节省时间）

使用 delegate_task 派发两个子代理同时提取 PDF 文本：

```
子代理 1: 提取主论文全部章节文本
子代理 2: 提取白皮书全部章节文本
```

### 2. 主论文独立分析

按标准流程完成论文的 Phase 2（元数据）+ Phase 3（逐章翻译精炼）。

### 3. 白皮书分析（作为附A）

在 running_notes.md 中以 `## 附A. 白皮书深度分析` 标题单独成章：

- **定位说明**: 文档类型、发布方、版本、篇幅
- **协议架构层次**: 分层图示（应用层→传输层→可靠交付层→拥塞控制→路径选择→网络层）
- **关键协议细节**: 论文提及但未展开的部分（报文格式、状态机、API 设计）
- **论文 vs 白皮书对照表**: 维度对比（目标读者、内容侧重、技术深度等）
- **深度洞察**: 白皮书揭示的论文未明言的设计决策

### 4. 深度分析（作为附B）

`## 附B. 深度分析` 覆盖论文和白皮书的综合分析：

- 优势（含白皮书验证的设计决策）
- 不足（含白皮书暴露的复杂度）
- 可复现性
- 开放问题
- 关键数据汇总表

## 笔记结构示例

```
## 0. 论文一页版总结
## 0. 摘要
## 1-7. 主论文章节分析
## 附A. MRC 白皮书深度分析
### A.1 白皮书定位
### A.2 协议架构层次
### A.3 关键协议细节
### A.4 白皮书 vs 论文的关系
### A.5 白皮书的深度洞察
## 附B. 深度分析
### B.1 优势
### B.2 不足
### B.3 可复现性
### B.4 开放问题
### B.5 论文中的关键数据
```

## 注意事项

- 白皮书可能在 Windows 桌面（`/mnt/c/Users/<user>/Desktop/`）→ 用 search_files 查找后 cp 到分析目录
- 长白皮书（70+页）的子代理提取时间约 90 秒，提前告知用户
- 白皮书分析侧重"论文未展开的技术细节"，避免重复论文已有的高层描述
