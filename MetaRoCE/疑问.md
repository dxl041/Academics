## B. 规范留下的空白（读文时记下的内部张力）

- [ ] **B1** **与 fabric 逐包喷洒的兼容性代价**：§4.6.1 承认 SACK 判丢依赖"同一 flow 不被网络重排"，并要求实现支持两种降级模式（关 SACK 判丢 / 只在 MaxFSN 减去若干窗口时才推进 snd.cur）。那么交换机开 per-packet spraying 时，尾延迟与吞吐到底退化多少？规范没给任何量化或推荐阈值（"configurable fraction of flow window"是什么量级？）。
- [ ] **B2** **`fwnd_floor` 与低编号流保护**（§6.3.3）：用 flow ID 判定"受保护"是因为便宜，但多 QP 共享同一条拥塞链路时，所有 QP 的 flow 0–3 都被保护，公平性是否偏向这些流？规范没讨论跨 QP 公平。
- [ ] **B3** **`QWND` 分数部分与 `β·QWND` 的整数算术**：§6.1.2 说"β·QWND<1 时可能连分数都不减"，并称这是"有意为之，鼓励换到未拥塞的流"。但若网卡实现里分数精度有限（多少 bit 未规定），长尾下是否会出现窗口永不下降？规范未给精度下限。
- [ ] **B4** **SRQ 防死锁的两种实现**（§3.4.1）只给了"可以怎么做"，未要求哪一种；不同厂商选不同策略时，wire 上无法互检——合规套件能否覆盖？仓库里是否有对应测试用例？（待查 `repo/` 的测试目录）
- [ ] **B5** **Tag 数量与 verbs 映射**：§10.6.1 规定 `qp_num` 高 8 bit 存 tag、低 24 bit 存 QPN，因此 tag 上限 256；§9.1 只要求"至少 4 个（Should）、最多 256（may）"。真实训练里 DP×PP×TP 叠加可能产生几十个通信域，加上每 Tag 独立 WQ/CQ（§10.6 表 10.1），网卡上 per-tag 队列状态是否比"多开 QP"更省资源？规范未给 per-tag 面积/内存预算。
- [ ] **B6** **RNR 冻结 CumulativeFSN 与多路径 UNA 的交互**（§4.9 + §4.10）：UNA 在多路径下落后是常态，而 RNR 期间 CumulativeFSN 冻结，二者叠加时接收端 per-FSN 状态释放会不会长期滞后（内存压力）？规范只说"发送端推进 UNA"。
- [ ] **B7** **mCRC 与 PSP/ESUN 的取舍**（§4.1 Fig 4.1）：ESUN 下必须带 mCRC，PSP 下必须不带。若同一 QP 跨两种封装（例如跨域时换封装），状态如何迁移？规范未提。
